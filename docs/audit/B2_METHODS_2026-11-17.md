## 1. Historical training-budget asymmetry

- The final RF runner (`scripts/54_run_rf_full.py`) originally fitted on
  **train + validation**: seed 42 uses 713,348 snapshots for fit.
- The final XGB runner (`scripts/53_run_xgb_full_gpu_fixed_v3.py`) fitted
  only on **train** (571,428 snapshots for seed 42) and used the separate
  validation set for early stopping.
- Identical test replay IDs and metrics do not by themselves make this
  original fitting-budget comparison a controlled head-to-head experiment.
- B2 added `--fit-partition train` to the RF runner with an explicit
  nonhistorical `--output-root` requirement. Default `train_val` preserves
  the old runner behavior. The returned JSON records `fit_partition` and
  `n_rows_fit`.

### Retrospective matched train-only comparison

The project already preserved **three train-only RF runs** under
`results/rf_calibration/real_v3_1_fixed/` and three train-only XGB runs under
`results/xgb_calibration/real_v3_1_fixed/`.

`scripts/66_check_matched_train_budget.py` reads all six saved runs and
recomputes test metrics from saved predictions. It verifies, for each seed:

- identical numbers of train, validation and test snapshots;
- the same replay IDs, snapshot timestamps and labels in both validation and
  test files;
- no replay overlap between validation and test;
- recomputed Accuracy, Balanced Accuracy, ROC-AUC and Log Loss agree with each
  archived `metrics_summary.json`.

Saved publication: `results/b2_fit_budget/retrospective_train_only.csv`.

| Three-seed mean | RF no_counter | XGB full |
|---|---:|---:|
| Accuracy | 0.612270 | 0.612792 |
| Balanced accuracy | 0.610068 | 0.609328 |
| ROC-AUC | 0.658147 | 0.660058 |
| Log loss (lower better) | 0.651698 | 0.648437 |

The model gap is small. **No formal statistical significance claim** is
supported by these three seed means. XGB used the same validation set for
early stopping whereas RF used fixed parameters; fit-row equality is not
identical tuning. All associated test scores are **historical** and had
already been inspected during project development.

## 2. Deep MLP test gating

Prior `scripts/64_run_deep_finalist.py` computed a test prediction for every
candidate while selecting a winner using validation metrics. Thus the
historical description of the test being used exactly once was inaccurate.

B2 changes:

1. `run_candidate` accepts **train and validation only**, not test.
2. Candidate searches and their saved `validation_search_results.csv`
   contain **validation metrics only**.
3. Only **after winner selection** is the selected model reconstructed from
   the fitted scaler and saved best state and evaluated on test.
4. `test_evaluation_policy=selected_candidate_only` is written to new run
   metadata and the default output root is now `results/b2_deep_strict`.
5. The train seed now follows the explicit split JSON seed.

A synthetic 2-candidate integration test confirmed **two validation
inferences + one test inference**, with no test-prefixed search columns.
Historical deep results stay unchanged; this code fix does not make them
retroactively blind.

## 3. Calibration guard and strict four-way rerun

The historical `scripts/63_run_rigorous_calibration.py` fitted logistic
(Platt-style) and isotonic mappings on validation predictions, not test labels.
However the XGB prediction runner used **the same validation partition for
early stopping**: the calibration fitting set was therefore not independent
of tuning. Moreover, the historical test data had already been inspected.

B2 adds:

- Replay-level non-overlap, duplicate snapshot, binary-target and
  probability-validity checks to the existing calibration runner.
- `scripts/67_run_strict_calibration.py`, a separate **four-way** runner
  partitioning each original validation group set deterministically into
  **tuning** and **calibration** replay groups, without changing the original
  train or test groups.
- RF and XGB fit **train only**. XGB early stopping uses **tuning only**.
  Logistic and isotonic calibrators fit **calibration only**. Final scores use
  test after model selection and calibration fitting.
- Disjoint split manifests, per-method test predictions, accuracy, balanced
  accuracy, ROC-AUC, log loss, Brier, ECE(15) and MCE(15) are saved to a new
  output directory. Existing run directories cannot be silently overwritten.

The new four-way protocol removes the internal tuning/calibration overlap,
but does not resurrect a never-inspected historical test set.

## FAIR full-size batch execution prepared — 2026-11-19

A new source-controlled Bash entry point,
`scripts/74_run_b2_full_fair.sh`, has been prepared to execute the
previously specified **nine** distinct full-size runs against the frozen
`real_v3_1_fixed` dataset:

- 3 replay-aware seeds (42, 43, 44) × 2 families (RF no-counter,
  XGBoost full), each via `67_run_strict_calibration.py` and
  train/tuning/calibration/test partitions;
- 3 seed-specific Deep candidate searches via
  `64_run_deep_finalist.py`, with test inference restricted to the
  validation-selected winner.

It is a guarded, **opt-in** execution entry point. By default
`bash scripts/74_run_b2_full_fair.sh --plan` prints the nine exact
commands without training. Run
`bash scripts/74_run_b2_full_fair.sh --execute` from the protected
audit branch on FAIR only after reviewing the plan and GPU availability.

Default new output namespace:
`results/b2_fullscale_audit_20261119/`. Set `B2_OUT_BASE`
to a different isolated path if an earlier attempt already wrote
partial results. All nine stdout/stderr streams have separate
`logs/{rf,xgb,deep}_seed_{42,43,44}.log` files.

The runner checks the current branch, frozen full ZIP, all three
split files, original reference calibration directories, CUDA on
actual execution, frozen payload hashes, and historical matched-fit
retrospective evidence. Existing complete outputs are skipped, and
incomplete output directories cannot be overwritten. RF uses 8 CPU
threads by default; XGB and Deep use the selected CUDA device.
The script does **not** alter historical outputs or the independent
sequential branch.

**No full-scale runs are asserted complete by preparing this script.**
Before changing B2's release flag, inspect all nine run summaries,
three-way calibration outputs, replay-disjoint split manifests, model
selection/test-use policy and per-seed uncertainty. The original test
was previously seen; do not call these newly blind results.
